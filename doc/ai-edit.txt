Edit a whole in-memory buffer or an exact characterwise/linewise selection.
Pi runs headlessly with one code-only prompt. Successful results stay unsaved
and can be reverted with one `u`. Blockwise selections are unsupported.

==============================================================================
1. SETUP                                                   *ai-edit-setup*

Requirements: Neovim 0.11+, macOS or Linux, Pi 1.1.0+, and Node.js 22.19+. Install Pi: >sh
  npm install -g --ignore-scripts @earendil-works/pi-coding-agent
<
Lazy setup: >lua
  {
    'vichr-vita/ai-edit.nvim',
    main = 'ai_edit',
    opts = {},
  }
<
Other package managers must add the repository root to 'runtimepath', then: >lua
  require('ai_edit').setup({})
<
Configure a model and credentials in the dedicated Pi directory. Its default
is stdpath('config') .. '/ai-edit/pi', normally ~/.config/nvim/ai-edit/pi.
For subscription authentication, start Pi separately: >sh
  PI_CODING_AGENT_DIR="$HOME/.config/nvim/ai-edit/pi" pi
<
Run /login, then choose and save a model with /model. For API keys, export your
provider key before starting Neovim and set the plugin's model option.

Only defaultProvider and defaultModel are read from settings.json. auth.json
and models.json are linked into each private run configuration. OAuth refreshes
update credentials in the dedicated directory. Regular Pi settings and project
configuration are not inherited.

2. OPTIONS                                               *ai-edit-options*

Defaults: >lua
  require('ai_edit').setup {
    keymap = '<leader>ai',
    command = 'pi',
    config_dir = vim.fn.stdpath('config') .. '/ai-edit/pi',
    model = false,
    thinking = 'off',
    timeout_ms = 300000,
    max_bytes = 1048576,
    width = 0.5,
    height = 0.2,
    status = {
      text = 'AI is Working...',
      color = '#d946ef',
      interval_ms = 80,
      frames = { '⠋', '⠙', '⠹', '⠸', '⠼', '⠴', '⠦', '⠧', '⠇', '⠏' },
    },
  }
<
                                                       *ai-edit-option-keymap*
keymap: non-empty global normal and visual mapping.
                                                      *ai-edit-option-command*
command: executable name or path, without shell arguments.
                                                   *ai-edit-option-config_dir*
config_dir: dedicated Pi model and authentication configuration directory.
                                                        *ai-edit-option-model*
model: false or provider/model text. false uses the dedicated Pi defaults.
                                                     *ai-edit-option-thinking*
thinking: off, minimal, low, medium, high, xhigh, or max. Pi clamps the level
  to model capabilities. Default off prioritizes immediate code output.
                                                   *ai-edit-option-timeout_ms*
timeout_ms: positive integer limiting run duration.
                                                    *ai-edit-option-max_bytes*
max_bytes: positive integer limiting the full buffer and replacement sizes.
                                                        *ai-edit-option-width*
width: fraction of editor width, greater than 0 and at most 1.
                                                       *ai-edit-option-height*
height: fraction of usable editor height, greater than 0 and at most 1.
                                                       *ai-edit-option-status*
status: status.text, status.color, status.interval_ms, and status.frames.
  text and each frame must be
  non-empty strings; frames must be a non-empty list. color must be a six-digit
  hex color. interval_ms must be a positive integer.

Unknown or invalid options fail during setup. OpenCode's variant and
cleanup_timeout_ms options have been removed. Use thinking for reasoning level.
Repeated setup replaces package mappings, commands, and autocommands.
Active jobs retain their captured options.

==============================================================================
3. MAPPINGS AND PROMPT                                  *ai-edit-mappings*

Normal mode edits the whole buffer. Characterwise and linewise visual mode
replace only the selection, using the full buffer as read-only context.

<CR> submits a non-empty instruction. <C-j> inserts a newline.
<C-p>/<C-n> recall older/newer instructions. <Up>/<Down> navigate history at
first/last input lines. <Esc> closes the prompt.

History stores the newest 100 accepted instructions in memory only. The fixed
code-only prompt is lua/ai_edit/prompt.md. It requests replacement code
immediately, with no fences, explanations, questions, tests, or verification.

==============================================================================
4. COMMANDS                                             *ai-edit-commands*

:AIEditCancel                                           *:AIEditCancel*
  Cancel active work for the current target buffer.

Lua: >lua
  require('ai_edit').cancel()       -- Current buffer.
  require('ai_edit').cancel(bufnr)  -- Specific buffer.
<
Cancellation and timeout discard output and leave target text unchanged.

==============================================================================
5. STATUSLINE                                         *ai-edit-statusline*

statusline() returns an escaped animated indicator during work, or an empty
string while idle. statusline_color() returns a lualine-compatible color table.
Example: >lua
  {
    require('ai_edit').statusline,
    color = require('ai_edit').statusline_color,
  }
<
Load lualine after AI edit when using direct function references. The target
stays locked while Pi runs; other buffers remain usable. The activity view
shows streamed code. Completed output applies as one undoable edit.

==============================================================================
6. HEALTH                                                 *ai-edit-health*

:checkhealth ai_edit checks Neovim, operating-system support, and Pi executable
discovery. It reports config_dir without launching Pi or contacting a model.

==============================================================================
7. SECURITY                                             *ai-edit-security*

Each edit runs once with an attached read-only snapshot of the unsaved buffer.
The model has no tools. Extensions, MCP, skills, prompt templates, context files,
themes, project configuration, and saved sessions are disabled. The model cannot
read other files or execute commands. The plugin applies the final response.

Private run settings disable compaction, retries, telemetry, cache warming, and
automatic network activity. Model requests and credential refreshes still use
the network. Local auth.json and models.json are trusted configuration.

==============================================================================
8. DATA LIFECYCLE                                           *ai-edit-data*

Results stay modified and unsaved. Press u once to restore the prior text.
The target must still match its captured revision before a result applies.
Incomplete or failed Pi responses are discarded.

Prompt and activity buffers disable swap. Activity output is bounded.
Staging files and run configuration are removed on completion or cancellation.
Dedicated credentials persist. A crash can leave staging data under
stdpath('cache')/nvim-ai-edit/staging. Provider retention policies apply.

==============================================================================
9. TROUBLESHOOTING                              *ai-edit-troubleshooting*

Executable not found: install Pi or set command to its executable path.
Unknown Pi option: update Pi to a current release.
Authentication/model error: configure Pi with PI_CODING_AGENT_DIR=config_dir.
Setup error: correct the named option. variant and cleanup_timeout_ms are gone.
Prompt unavailable: use a named writable non-binary file and adequate space.
Stale result: retry from the current buffer without changing it during the run.
Timeout: increase timeout_ms or reduce request scope.

Contributor checks: bun tests/ai_edit/run.ts all. Use fake or pi to run each
check group separately. Installed Pi checks use a local provider stub and need
no credentials. CI uses Pi 1.1.0 on Linux and macOS.
